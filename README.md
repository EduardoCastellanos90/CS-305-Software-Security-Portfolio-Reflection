# CS-305-Software-Security-Portfolio-Reflection
Artemis Financial Security Assessment and Secure Software Development
For this project, I worked with Artemis Financial, a financial services company that needed to improve the security of its web application. The company wanted to ensure that sensitive client information was protected through secure communications and data integrity controls. My task was to identify potential vulnerabilities, assess associated risks, and implement security improvements that would strengthen the application's overall security posture.

One area where I performed well was learning how to identify vulnerabilities and evaluate their potential impact on the application. Through this process, I implemented SHA-256 hashing to verify data integrity, configured SSL/TLS certificates to support secure HTTPS communications, and used OWASP Dependency-Check to identify known vulnerabilities within project dependencies. This experience reinforced the importance of secure coding practices because security is not just about protecting data. It also helps maintain customer trust, reduce organizational risk, support compliance requirements, and protect a company's reputation. One of the most challenging yet valuable parts of the project was interpreting vulnerability assessment results and learning how to prioritize mitigation efforts based on risk rather than simply addressing issues individually.

To increase security, I applied multiple layers of protection instead of relying on a single control. These layers included secure communications through HTTPS, SSL/TLS certificate configuration, SHA-256 hashing, dependency analysis, and additional testing after code modifications. In future projects, I would continue using vulnerability assessments, dependency scanning tools, OWASP guidance, secure coding standards, and risk-analysis techniques to identify vulnerabilities and select appropriate mitigation strategies. After implementing security improvements, I verified that the Spring Boot application continued to function correctly by testing application startup, HTTPS connectivity, server configuration, and checksum generation. I also reran OWASP Dependency-Check scans to confirm that my changes did not introduce new vulnerabilities.

Several resources and tools were especially useful throughout this project, including Spring Boot security configuration, Java Keytool for certificate generation, SHA-256 hashing with the MessageDigest class, OWASP Dependency-Check, and OWASP secure development practices. These tools helped me better understand vulnerability management, encryption technologies, dependency management, and secure software development. If I were presenting this project to a future employer, I would use it as an example of my ability to assess software vulnerabilities, implement security controls, configure encrypted communications, perform security testing, and apply secure development practices throughout the software development lifecycle. This project demonstrates both technical problem-solving skills and an understanding of the importance of building security into software from the beginning rather than treating it as an afterthought.
